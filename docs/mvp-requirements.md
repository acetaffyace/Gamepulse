# 游戏长线运营情报看板 MVP 需求文档

**文档状态：** Draft / MVP 基线  
**版本：** 0.1  
**首个示例游戏：** 《绝区零》（Zenless Zone Zero）  
**产品定位：** Steam 公开数据 + B 站登记视频播放量的轻量趋势雷达

---

## 1. 产品概述

### 1.1 定位

本项目用于观察游戏在较长时间窗口内的公开运营信号：

- Steam 同时在线人数；
- Steam 好评率和评测规模；
- 当前价格与折扣；
- 版本、DLC、活动、维护和官方公告节点；
- Steam 新增评测（讨论热度代理）；
- B 站登记视频的播放量及增量。

它是个人研究和作品集项目，不是游戏公司的内部经营系统。不展示或推断真实 DAU、收入、留存、付费率、LTV 或全平台用户数。

### 1.2 核心问题

1. 游戏近期的 Steam 在线关注度是上升还是下降？
2. 版本更新、活动或折扣附近，在线、好评率和评测热度是否出现变化？
3. 折扣是否与公开关注度变化同时出现？
4. B 站视频播放量是在持续增长，还是由单个视频拉动？
5. 多款游戏之间的版本节奏、折扣节奏和公开关注度有什么差异？

### 1.3 MVP 成功标准

- 默认打开《绝区零》；
- 以日为粒度保存快照，支持 7/30/90 天趋势；
- 在统一页面查看在线、好评率、价格/折扣、评测热度、版本事件和 B 站播放量；
- 版本/折扣事件可在趋势图上标记并回链来源；
- 新增第二款游戏只需添加配置，不修改核心图表代码；
- 每个数值都有来源、抓取时间和口径；
- 缺失、过期和异常数据不被静默填成 0。

## 2. 用户和使用场景

| 用户 | 场景 |
|---|---|
| 游戏运营/市场实习生 | 生成周度竞品观察和版本复盘 |
| 用户研究/游戏测评候选人 | 展示公开数据采集、趋势分析和业务表达 |
| 个人研究者 | 长期记录感兴趣游戏的公开热度变化 |

典型流程：

    选择游戏 → 选择时间范围 → 查看趋势 → 点击版本/折扣事件 → 追溯来源 → 导出周报

## 3. 范围与非目标

### 3.1 MVP 包含

- Steam 单款/多款游戏的每日公开快照；
- 《绝区零》默认配置；
- 通过 games.yml 添加其他游戏；
- Steam 当前同时在线人数；
- Steam 全部评价好评率、正面/负面评测数、总评测数；
- 新增评测数；
- Steam 当前价格、原价、折扣比例和货币；
- Steam News/官方公告中的版本、活动、DLC、维护事件；
- B 站人工登记 BV 号的视频播放量每日快照；
- 总览、单游戏详情、游戏对比、数据口径四类页面；
- CSV 和一页 Markdown/HTML 周报导出；
- 采集日志、来源追溯和基础质量检查。

### 3.2 明确不做

- 内部 DAU、收入、留存、付费、LTV、流失预测；
- 玩家级画像、用户识别、私信或社区自动操作；
- 自动搜索全部 B 站相关视频；
- 声称覆盖 B 站全站播放量或全网讨论量；
- 复杂评论主题建模、工单和团队协作流；
- 登录后采集、验证码破解、反检测和绕过风控；
- 将时间上的共现写成版本导致在线/留存变化的因果结论；
- 使用模型或随机数补齐历史数据。

## 4. 数据源与边界

### 4.1 数据源

| 数据 | 首选来源 | 采集方式 | 频率 | 级别 |
|---|---|---|---|---|
| 当前在线人数 | Steam Web API GetNumberOfCurrentPlayers | 公开 JSON | 每日 | 必需 |
| 好评率/评测数 | Steam Reviews API appreviews | 公开 JSON | 每日 | 必需 |
| 当前价格/折扣 | Steam Store appdetails | 公开 JSON | 每日 | 必需 |
| 版本/公告 | Steam News API、官方公告页 | 公开 JSON/页面，必要时人工确认 | 每日/事件发生时 | 必需 |
| 在线历史峰值 | SteamDB / Steam Charts 等公开来源 | 公开页面、可复现导出或手工导入 | 每日/周度 | 可选 |
| 价格历史/版本构建 | SteamDB | 公开页面/导出；受访问限制时手工导入 | 每日/事件发生时 | 可选增强 |
| B 站播放量 | 视频页公开字段或公开信息接口 | BV 号注册表 + 公开读取 | 每日 | 必需 |

### 4.1.1 Steam 与 SteamDB 的职责划分

- **Steam 官方 API/Store/News：** 当前在线、当前价格、评测摘要和新闻事件的首选主源；
- **SteamDB：** 历史在线曲线、价格历史、版本构建/更新时间等公开信息的补充源；
- SteamDB 是第三方站点，不是 Valve 官方数据源，字段、访问方式和历史覆盖可能变化；
- SteamDB 可能出现 403、Cloudflare、限流或需要浏览器渲染的情况，MVP 不绕过这些限制；
- 同一指标冲突时保留来源信息，当前值默认官方源优先，历史补充值标记为 `third_party` 或 `manual_backfill`；
- 不把 SteamDB 的估算玩家数、所有者数等字段当作精确事实，除非明确标注其估算性质。

### 4.2 记录级元数据

每条记录至少保存：

- source_url；
- captured_at；
- source_type；
- 原始响应快照路径；
- quality_status；
- 覆盖范围说明（如“Steam 平台”“登记视频集合”）。

数据性质标签：

| 标签 | 含义 |
|---|---|
| observed | 公开来源直接读取 |
| derived | 由公开值计算，如好评率、新增评测 |
| proxy | 部分公开信号，如讨论热度代理 |
| manual | 人工登记或确认的事件/视频 |
| unavailable | 当前无法获得 |

### 4.3 《绝区零》前置检查

公开检索可解析到《绝区零》的 Steam App ID **4162040**；当前玩家数接口可以返回值，但 Store 详情接口可能返回 `success: false`。M0 必须逐字段确认可用性，不能只因为存在 App ID 就假设价格、评测和新闻字段完整。

若某字段不可用：

- 在字段级别标记 `unavailable`，而不是用 0 代替；
- 不伪造 Steam 趋势；
- 可先用有稳定 Steam App ID 的游戏验证采集链路；
- B 站模块可独立开发；
- README 明确具体数据缺口和检查日期。

### 4.4 B 站视频注册表：按角色/版本组织

用户的 BV 号主要来自每个新角色上线时发布的视频，因此视频应挂在“角色内容事件”下，而不是孤立列表。MVP 不做全网自动搜索，采用人工登记 BV 号。

每个角色可登记以下内容类型（有则登记，无则留空）：

- `character_trailer`：角色 PV/预告；
- `character_demo`：角色试玩/战斗演示；
- `character_ep`：角色 EP、音乐或剧情短片；
- `character_guide`：媒体/创作者攻略或解析（可选）；
- `version_trailer`：版本前瞻或版本 PV（可选）。

每条视频记录：

- BV 号、游戏 ID、角色 ID/角色名（可空）；
- 版本号/版本周期（可空）；
- 内容类型：official、media、creator、guide、other；
- 视频标题、UP 主、发布时间（可得时）；
- 详情页 URL、登记日期、是否启用；
- `is_official_account` 和覆盖说明。

删除、不可访问或字段缺失时记录状态，不估算数值；同一 BV 号只能登记一次。一个角色可以关联多个视频，一个视频只能归属于一个游戏，但可通过 `character_id` 和 `version_id` 归档到对应事件。

推荐注册表结构：

```yaml
videos:
  - bvid: BVxxxxxxxxxxx
    game_id: zenless_zone_zero
    character_id: character_001
    character_name: <角色名>
    version_id: 1.4
    content_type: character_demo
    title: <视频标题>
    creator: <UP主>
    is_official_account: true
    active: true
```

看板可按角色、版本、官方/创作者和视频类型筛选；首页默认显示官方角色视频汇总，创作者视频作为可选增强，避免单个爆款视频扭曲官方内容趋势。

## 5. 指标字典

### 5.1 首页 KPI

默认首页只展示：

1. 当前在线观测值；
2. 最近 7 日平均在线观测值；
3. 当前 Steam 全部评价好评率；
4. 最近 7 日新增评测数；
5. 当前价格和折扣；
6. 最近版本/公告日期。

无数据时显示“暂无数据”，不显示 0。

### 5.2 在线人数 current_players

- Steam API 返回的当前同时在线玩家数；
- 仅代表 Steam 平台；
- 不得标记为 DAU、活跃用户数或总玩家数；
- 日序列默认使用北京时间固定时点快照；
- 多次采集时可另存 daily_observed_max，但标注为观测最大值；
- 缺失天数保持断点，不线性补齐。

### 5.3 好评率 positive_rate

- 公式：total_positive / total_reviews；
- 展示为百分比，保留 1 位小数；
- 默认使用累计全部评价好评率；
- 若 API 提供近期评价，另存 recent_positive_rate，不可与累计值混用；
- 累计好评率变化较慢，不直接等同于最近一周评论质量。

### 5.4 新增评测/讨论热度代理

- 公式：当日总评测数 - 上一条有效快照总评测数；
- 展示名称：“Steam 新增评测（讨论热度代理）”；
- proxy 标签始终可见；
- 负差值标记为平台修正、历史重算或抓取异常；
- 不得称为全网讨论量、社区总发言量或玩家总讨论人数。

若未来获得 Steam 社区讨论帖数量，作为独立指标 steam_discussion_posts，不与新增评测直接相加。

### 5.5 价格/折扣

保存 initial_price、final_price、discount_percent、currency、is_free。

- 默认中国区参数和返回货币；
- 展示原价、折后价、折扣比例；
- 免费游戏显示“免费”；
- 免费游戏不绘制无变化的折扣趋势；对应位置显示“免费游戏，暂无本体折扣”，价格模块仍为后续付费游戏保留；
- 如果未来跟踪公开销售的 DLC/礼包，必须作为独立商品 ID 和独立价格序列，不能混入游戏本体价格；
- 价格历史只代表项目开始采集后的快照；
- 不同地区货币不可直接比较；
- 折扣开始、结束、折扣变化和恢复原价生成价格事件。

### 5.6 版本事件

事件类型：patch、dlc、season、event、maintenance、official_news、sale。

每个事件保存：

- 事件 ID、游戏 ID、日期；
- 标题、摘要；
- 来源名称和 URL；
- auto_detected / user_confirmed / rejected 状态。

事件只表示时间节点，不自动判断因果。

### 5.7 B 站播放量

- view_count 为公开视频播放量快照；
- view_delta = 当日播放量 - 上一条有效快照播放量；
- 负差值标记为平台修正或异常；
- 首页展示登记视频数、总播放量和近 7 日播放量增量；
- 总播放量标注为“登记视频集合”，不等同于独立观众数；
- 视频类别可筛选。

## 6. 数据模型

### 6.1 实体关系

    Game → SteamDailySnapshot / SteamPriceSnapshot / VersionEvent / BilibiliVideo → BilibiliDailySnapshot

### 6.2 核心表

#### games

| 字段 | 类型/说明 |
|---|---|
| game_id | 稳定主键 |
| display_name | 显示名 |
| steam_app_id | 可空 |
| steam_status | available/unavailable/pending |
| region | 默认 CN |
| currency | 可空 |
| active | 布尔值 |
| created_at | 时间戳 |

#### steam_daily_snapshots

字段：snapshot_id, game_id, captured_at, date_local, current_players, daily_peak_players, total_reviews, total_positive, total_negative, all_time_positive_rate, recent_positive_rate, new_reviews, source_url, raw_snapshot_path, quality_status。

#### steam_price_snapshots

字段：price_snapshot_id, game_id, captured_at, date_local, currency, is_free, initial_price_minor, final_price_minor, discount_percent, source_url, raw_snapshot_path, quality_status。

#### version_events

字段：event_id, game_id, event_date, event_type, title, summary, source_url, source_name, verification_status。

#### bilibili_videos

字段：bvid, game_id, character_id, character_name, version_id, content_type, title, creator, is_official_account, published_at, active, registered_at, source_url。

#### bilibili_daily_snapshots

字段：bilibili_snapshot_id, bvid, captured_at, date_local, view_count, like_count, comment_count, quality_status, source_url, raw_snapshot_path。

### 6.3 去重规则

- game_id 是内部稳定 ID，不使用显示名称做主键；
- steam_app_id 可用时唯一；
- bvid 全局唯一；
- Steam 逻辑唯一键：game_id + date_local + source；
- B 站逻辑唯一键：bvid + date_local；
- 重复抓取保留 raw response，派生视图使用最后一条通过质量检查的记录；
- 原始快照不可覆盖，修正产生新记录或明确标记。

## 7. 页面和布局

### 7.1 总览页 Overview

默认：游戏=《绝区零》；时间=最近 30 天。

顶部控件：

- 游戏选择器；
- 时间范围：7 天、30 天、90 天、自定义；
- 可选对比游戏；
- 最近刷新时间和覆盖区间。

主要区域：

1. KPI 条：在线、7 日平均在线、累计好评率、7 日新增评测、当前折扣、最近事件日期；
2. 在线趋势折线图；
3. 好评率趋势折线图；
4. Steam 新增评测柱状图；
5. B 站播放趋势图；
6. 版本/折扣/活动事件时间线；
7. 最近事件表和来源链接。

### 7.2 单游戏详情页 Game Detail

- 在线趋势；
- 好评率、评测总数和新增评测；
- 价格/折扣历史；
- B 站视频明细、分类和单视频播放趋势；
- 版本/活动/公告列表；
- 数据质量和来源信息。

### 7.3 游戏对比页 Compare

支持 2–3 款游戏，默认展示：

- 在线趋势指数化（首日=100）；
- 好评率变化；
- 新增评测趋势；
- 折扣状态和版本事件时间分布；
- B 站登记视频集合的播放量增量。

不同量级游戏不默认比较绝对在线人数；详情表可查看绝对值并显示平台限制。

### 7.4 数据与口径页 Data & Method

必须列出：

- 数据源 URL/名称；
- 最近抓取时间；
- 指标公式和单位；
- observed/derived/proxy/manual/unavailable 含义；
- Steam 平台限制；
- B 站注册表覆盖限制；
- 缺失、过期、重复和倒退值处理规则；
- 不能由公开数据推出的结论。

## 8. 交互要求

### 8.1 筛选

- 游戏和时间筛选同时影响 KPI、趋势图和事件表；
- 清空筛选恢复“《绝区零》+ 最近 30 天”；
- 不可用游戏保留在选择器中并显示状态；
- 视频类别筛选只影响 B 站模块。
- 角色和版本筛选只影响 B 站角色视频模块及相关事件摘要；
- 首页默认只显示官方角色视频，详情页可切换媒体/创作者/攻略视频。

### 8.2 图表

- hover 显示日期、数值、单位、来源性质和质量状态；
- 点击事件标记显示标题、类型、日期和来源 URL；
- 在线、好评率、播放量不在同一张绝对值双轴图混放；
- B 站支持“总播放量/日增播放量”切换；
- 指数化对比显示基准日。

### 8.3 错误和空状态

- 缺失数据显示断点或暂无数据；
- API 失败可保留最近有效值，但显示快照日期和过期提示；
- 超过 48 小时未更新显示“数据可能过期”；
- 播放量/评测数倒退显示异常提示；
- 没有 Steam App ID 的游戏不显示伪造趋势。

### 8.4 导出

- 当前筛选范围导出 CSV；
- 生成一页周报，包含趋势摘要、事件、覆盖日期、来源和限制；
- 导出不含 API Key、Cookie、Authorization header 或本机绝对路径。

## 9. 采集、存储与刷新

### 9.1 处理链路

    读取配置 → 请求公开数据 → 保存 raw response → 规范化 → 计算派生指标 → 质量检查 → 写入派生表 → 看板读取

### 9.2 刷新规则

- 默认每天 1 次，建议北京时间 12:00–14:00；
- 支持按游戏手工重跑；
- 失败后低频重试，不进行高频请求；
- MVP 不要求实时刷新；
- 采集脚本与看板进程分离。

### 9.3 历史数据

- 在线、价格和 B 站播放量主要依赖项目启动后的每日快照；
- 评测总数/好评率可获取累计值，但不假设有可靠历史序列；
- 历史版本事件可人工补录，标记 backfilled 并带来源；
- 缺少历史快照时显示实际覆盖天数，不用合成数据延长曲线。
- B 站角色视频的历史播放量从首次登记/首次采集日开始计算；登记前的播放量只能作为当日累计值，不能推导历史日增量。

## 10. 技术方案

### 10.1 推荐栈

Python 3.11+、requests/httpx、Pandas、DuckDB 或 SQLite、Parquet、Streamlit、Plotly、GitHub Actions（可选）、Markdown/HTML 导出。

### 10.2 推荐目录

    game-ops-radar/
    ├── config/
    │   ├── games.yml
    │   └── bilibili_videos.yml
    ├── data/
    │   ├── raw/steam/

## 11. 数据质量与监控

### 11.1 必做检查

- 必需字段存在；
- 主键/逻辑唯一键不重复；
- 在线、评测、价格、播放量为非负数；
- 好评率在 0–100%；
- 折扣在 0–100；
- 时间戳不晚于当前时间；
- BVID 有效且不重复；
- 评测总数和播放量倒退被标记；
- Steam App ID 与配置一致；
- 最近有效快照不超过 48 小时；
- 展示值可追溯到来源快照。

### 11.2 质量状态

| 状态 | 行为 |
|---|---|
| ok | 正常展示 |
| partial | 展示可用字段并提示缺失 |
| stale | 展示最近值并提示过期 |
| invalid | 不进入趋势计算，写入错误日志 |
| unavailable | 显示暂无数据 |

### 11.3 告警

日志和口径页显示：连续两次失败、超过 48 小时未更新、字段缺失、数量倒退、连续 7 天无有效快照。

## 12. 趋势提示与 AI 周报

### 12.1 规则型提示

可生成“值得关注”提示：

- 版本事件后 7 天新增评测高于前 7 天；
- 折扣期间在线观测值高于近期基线；
- 好评率变化超过历史波动区间；
- 某 B 站视频播放量增速高于同游戏其他登记视频；
- 版本事件与在线趋势断点时间接近。

每条提示显示比较窗口、计算规则、原始数据和来源，使用“可能/值得关注”，不使用“导致”。

### 12.2 AI 周报（可选）

AI 只接收通过质量检查的聚合数据、事件摘要和来源链接。输出分为：

- **事实：** 数据直接支持；
- **观察：** 谨慎的趋势描述；
- **待验证假设：** 可能解释；
- **限制：** 平台、样本和覆盖偏差。

禁止编造数值、版本、视频、平台覆盖或因果关系。

## 13. 隐私、合规与平台边界

- 只使用公开可访问数据；
- 不保存 Cookie、账号或 Authorization header；
- API Key 仅从环境变量读取；
- 原始评论文本非必要不进入最终看板；
- B 站只保存公开视频统计字段和链接；
- 遵守公开接口频率、robots 和平台服务条款；
- 不破解验证码、不绕过登录、不做反检测；
- README 声明“独立研究原型，不代表平台或游戏公司官方系统”。
